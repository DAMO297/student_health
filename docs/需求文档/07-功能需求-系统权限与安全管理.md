## 7. 功能需求——系统权限与安全管理模块

### 7.1 模块目标

建立统一的认证授权与安全防护体系，确保“不同角色只能访问授权资源”，并通过加密、审计、风控与缓存提升系统安全性与可用性。

### 7.2 认证（Authentication）

#### 7.2.1 登录

- **登录方式**：用户名/学号/工号 + 密码（可配置登录标识）
- **验证码**：可选启用（防爆破）
- **成功结果**：
  - 返回 JWT（Access Token）
  - 返回用户基础信息（userId、role、displayName、dataScope 摘要）
- **失败处理**：
  - 统一提示“账号或密码错误”（避免泄露账号是否存在）
  - 失败次数阈值后触发验证码或冻结

#### 7.2.2 注册（学生端，可选）

- 学号与姓名需与学生主档匹配（防止冒用）
- 注册后默认角色 ROLE_STUDENT
- 支持绑定手机号/邮箱（用于通知与找回）

#### 7.2.3 找回/重置密码（可选）

方式：管理员重置、邮箱/短信验证码重置（视实现难度选择）。

### 7.3 授权（Authorization）

基于 Spring Security + RBAC（详见 `02-角色与权限设计.md`）：

- **后端要求**：
  - 所有受保护接口必须做权限校验
  - 除角色外，必须叠加数据范围（Data Scope）校验
- **前端要求**：
  - 菜单/按钮根据权限点进行显隐
  - 不能仅依赖前端做权限控制（后端必须兜底）

### 7.4 传输与数据安全

#### 7.4.1 HTTPS（建议）

- 生产环境必须启用 HTTPS
- 本地开发可使用 HTTP，但需明确说明风险

#### 7.4.2 AES 加密（需求说明）

开题报告提出“通过 AES 保护数据传输安全”：

- **推荐做法（优先）**：HTTPS 负责传输安全；AES 用于敏感字段加密/脱敏（数据库落库或日志）
- **若必须对业务报文 AES**：
  - 对请求体中敏感字段（身份证、手机号等）加密
  - 需要定义密钥管理策略（密钥不落地在前端；可按会话协商或使用服务端公钥方案）

#### 7.4.3 敏感字段保护

敏感字段：身份证、手机号、邮箱、健康指标数据（可视为敏感个人信息）。

- **展示脱敏**：管理员/医生按需可见；学生仅见自己
- **导出保护**：导出需权限 + 水印（可选）+ 审计记录
- **日志脱敏**：请求参数/导出路径等不得打印敏感明文

### 7.5 Redis 缓存（性能与安全协同）

缓存目标：
- 降低热点查询（学生信息、字典阈值、报表统计聚合结果）对数据库压力
- 加速权限信息与 Token 失效管理（可选）

缓存规范：
- Key 命名规范：`app:{module}:{bizKey}`（例如 `health:student:20220101`）
- TTL：字典类可长 TTL；统计结果短 TTL；Token 黑名单按 exp
- 缓存一致性：写操作后主动失效相关 Key

### 7.6 防护与风控（最低要求）

- **防爆破**：登录失败次数限制 + 冻结策略
- **防重放**：可选 nonce/timestamp；或对关键操作加一次性 token
- **CSRF**：若使用 JWT 且前后端分离，按标准配置（一般可关闭 CSRF 但需确保不使用 Cookie 会话）
- **CORS**：严格限制来源域名与方法
- **限流**：对登录、导出、批量导入、统计接口做限流（可选）

### 7.7 审计日志（安全必需）

要求同 `02-角色与权限设计.md` 的审计清单，额外强调：
- 导入导出必须记录：文件名、hash（可选）、成功/失败数量
- 报告下载必须记录：报告编号、下载人、时间、IP

### 7.8 验收标准（本模块）

- JWT 鉴权有效：无 Token/过期 Token/伪造 Token 均无法访问受保护接口
- 越权测试通过：学生无法访问他人报告/记录；医生无法访问范围外数据
- 审计可追溯：关键业务操作均有日志记录且可查询
- 敏感信息不泄露：接口错误不返回堆栈；日志不打印敏感明文
