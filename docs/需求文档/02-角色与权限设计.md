## 2. 角色与权限设计（RBAC）

### 2.1 角色定义

系统内置三类角色（后续可扩展）：

- **ROLE_ADMIN（管理员）**
  - 全局配置、数据管理、用户管理、角色权限管理
  - 数据审核（可选流程）
  - 统计分析与报表导出
  - 任务调度与运维管理、审计日志

- **ROLE_DOCTOR（医生）**
  - 体检数据录入（单条/批量）
  - 报告生成、预览、修订
  - 可查看所负责范围内的学生体检数据（范围策略见 2.4）

- **ROLE_STUDENT（学生）**
  - 仅可访问本人数据：个人信息（可配置字段）、体检记录、体检报告、下载导出

### 2.2 资源与操作（权限点清单）

建议将权限点按“资源-动作”维度拆分，以便后续扩展到细粒度权限：

- **学生信息（student）**
  - student:read、student:create、student:update、student:delete、student:import、student:export

- **体检记录（exam_record）**
  - exam_record:read、exam_record:create、exam_record:update、exam_record:delete、exam_record:import、exam_record:export

- **体检报告（report）**
  - report:read、report:generate、report:update、report:delete、report:export_pdf、report:export_excel、report:print

- **统计分析（analytics）**
  - analytics:read、analytics:export

- **系统配置与字典（config/dict）**
  - config:read、config:update、dict:manage

- **用户与权限（user/role）**
  - user:manage、role:manage、permission:manage

- **日志与审计（audit）**
  - audit:read、audit:export、audit:clear（慎用）

- **任务调度（scheduler）**
  - scheduler:read、scheduler:manage、scheduler:trigger

### 2.4 数据范围策略（Data Scope）

为避免医生看到不相关数据，建议提供数据范围策略（可配置）：

- **按学院/年级/班级范围**：医生账号绑定可管理范围
- **按体检批次/任务范围**：医生仅访问被分配批次的学生
- **默认策略**：管理员全量；医生受限；学生仅本人

数据范围策略需要在后端查询层统一生效（例如 MyBatis 拦截器、Service 层集中校验），并在审计日志中记录访问范围命中结果。

### 2.5 认证与会话

- **认证方式**：账号密码登录 → 返回 JWT（Access Token）；可选 Refresh Token
- **Token 载荷（建议）**：
  - userId、username、role(s)、dataScope、tokenVersion、exp
- **登出**：客户端删除 Token；服务端可通过 tokenVersion 或黑名单（Redis）实现主动失效

### 2.6 审计与合规（权限相关）

必须记录的审计事件（最低要求）：

- 登录/登出、登录失败（含原因：密码错误/账号冻结/验证码失败等）
- 学生信息增删改、批量导入
- 体检记录增删改、批量导入
- 报告生成、导出、打印
- 权限/角色变更、账号状态变更
- 任务调度变更与手动触发

审计字段建议：操作者、角色、来源 IP、User-Agent、请求路径、请求参数摘要、结果（成功/失败）、耗时、时间戳。
